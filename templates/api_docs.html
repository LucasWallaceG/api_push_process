1. Visão geral

O que este serviço faz e como ele processa uma requisição.

Este serviço automatiza o cadastro e a exclusão de processos no Push do PJe (todos os TRTs). Você envia uma requisição HTTP; ela entra numa fila; um robô abre o PJe, executa a ação e devolve o resultado para o seu sistema. 

Seu sistema  ──POST──▶  API (fila)  ──▶  Worker (robô Selenium)  ──▶  PJe
                                                    │
                                                    └──POST de retorno──▶  Seu sistema (callback)

O processamento é assíncrono: o POST responde imediatamente (201, "enfileirado") e o resultado real chega depois, no seu callback.

Acompanhe em tempo real: o painel mostra cada requisição, seu status, a mensagem devolvida pelo PJe e o print da tela.

2. Base URL

Todos os caminhos deste guia são relativos a esta base.

{{ base_url }}

Rede: este serviço roda na rede interna. O host acima precisa estar acessível a partir de quem chama a API — e também do navegador do usuário, caso você exiba os prints de tela.

3. Endpoints

Resumo de tudo que a API expõe.

4. Cadastrar um processo no Push

Exemplo real, pronto para copiar.

Requisição — cURL

curl -X POST "{{ base_url }}push/received" \
  -H "Content-Type: application/json" \
  -d '{
    "numero_processo": "0000511-77.2025.5.06.0018",
    "tribunal": "6",
    "grau": "1",
    "acao": "create",
    "callbacks": [
      {
        "url": "http://192.168.11.24:3000/api/integracoes/push/retorno",
        "id": "ca53bfff-b8e5-4ab2-9776-3bbdead6113f",
        "token": "SEU_TOKEN_AQUI"
      }
    ]
  }'

Requisição — PowerShell (Windows)

$body = @{
  numero_processo = "0000511-77.2025.5.06.0018"
  tribunal        = "6"
  grau            = "1"
  acao            = "create"
  callbacks       = @(@{
      url   = "http://192.168.11.24:3000/api/integracoes/push/retorno"
      id    = "ca53bfff-b8e5-4ab2-9776-3bbdead6113f"
      token = "SEU_TOKEN_AQUI"
  })
} | ConvertTo-Json -Depth 5

Invoke-RestMethod -Uri "{{ base_url }}push/received" -Method Post `
  -ContentType "application/json" -Body $body

Requisição — Python

import requests

payload = {
    "numero_processo": "0000511-77.2025.5.06.0018",
    "tribunal": "6",
    "grau": "1",
    "acao": "create",
    "callbacks": [{
        "url": "http://192.168.11.24:3000/api/integracoes/push/retorno",
        "id": "ca53bfff-b8e5-4ab2-9776-3bbdead6113f",
        "token": "SEU_TOKEN_AQUI",
    }],
}

r = requests.post("{{ base_url }}push/received", json=payload, timeout=15)
print(r.status_code, r.json())

Resposta imediata (HTTP 201)

{
  "mensagem": "Encaminhado para fila de processamento!",
  "item": {
    "numero_processo": "0000511-77.2025.5.06.0018",
    "tribunal": "6",
    "grau": "1",
    "acao": "create",
    "req_id": "3f7c1e2a-9b44-4d51-8a10-6e2f0c9d5b77"
  }
}
Esta resposta significa apenas "aceito e enfileirado" — não que o cadastro já ocorreu no PJe. O resultado real chega no seu callback.

5. Excluir um processo do Push

Igual ao cadastro, mudando acao para delete.

Envie o codigo sempre que tiver. É o ID da assinatura de push devolvido no retorno do cadastro. Com ele, a exclusão é feita direto pela API do PJe — muito mais rápida e estável. Sem o codigo, o robô precisa varrer a tela página por página (um TRT pode ter milhares de processos). 
curl -X POST "{{ base_url }}push/received" \
  -H "Content-Type: application/json" \
  -d '{
    "numero_processo": "0000511-77.2025.5.06.0018",
    "tribunal": "6",
    "grau": "1",
    "acao": "delete",
    "codigo": 1701632,
    "callbacks": [
      {
        "url": "http://192.168.11.24:3000/api/integracoes/push/retorno",
        "id": "ca53bfff-b8e5-4ab2-9776-3bbdead6113f",
        "token": "SEU_TOKEN_AQUI"
      }
    ]
  }'
O codigo é por grau: o mesmo processo pode ter um código no 1º grau e outro no 2º. Guarde e envie o código correspondente ao grau da requisição.

6. Campos do payload

O que enviar no POST /push/received.

CampoTipoObrigatórioDescrição
numero_processostringSim Número CNJ completo. Ex.: 0000511-77.2025.5.06.0018
acaostringSim create (cadastrar) ou delete (excluir)
tribunalstringSim Número do TRT, sem zeros à esquerda. Ex.: "6" para o TRT6
graustringSim "1" = 1º grau · "2" = 2º grau
codigonúmeroNão Só no delete. ID da assinatura de push (vem no retorno do cadastro). Torna a exclusão muito mais rápida.
callbackslistaRecomendado Destinos do retorno. Cada item: url, id, token. Sem isso, o retorno vai para o webhook legado.
paginastringNão Só no delete sem codigo: dica de página para acelerar a busca na tela.
req_idstringNão Gerado automaticamente se ausente. Identifica a requisição no painel.

7. Retorno (callback)

O que o serviço envia de volta ao terminar — é aqui que está o resultado real.

Ao concluir, o serviço faz um POST para cada url da sua lista callbacks, com este corpo:

{
  "id": "ca53bfff-b8e5-4ab2-9776-3bbdead6113f",
  "status": "SUCESSO",
  "message": "processo cadastrado com sucesso",
  "token": "SEU_TOKEN_AQUI",
  "screenshot": "{{ base_url }}screenshots/0000511-77.2025.5.06.0018_create_SUCESSO_20260707_143512.png",
  "codigo": 1701632
}
CampoDescrição
idO mesmo id que você enviou no callback — use para casar com sua tarefa.
statusSUCESSO, AVISO ou ERRO.
messageMensagem real devolvida pelo PJe. Exiba-a literalmente ao usuário.
tokenO token que você enviou — valide-o antes de aceitar o retorno.
screenshotURL absoluta do print da tela. Pode não vir se a captura falhar.
codigoSó no create: ID da assinatura de push. Guarde-o e envie no delete.

Valores de status

Aguardando Processando Sucesso Aviso Erro

  • AGUARDANDO / PROCESSANDO — estados intermediários, visíveis no painel.
  • SUCESSO — ação concluída no PJe.
  • AVISO — concluída com ressalva (ex.: processo já estava cadastrado).
  • ERRO — falhou; a message traz o motivo e o screenshot mostra a tela.
Seu endpoint de retorno deve responder rápido (2xx). Se demorar mais que o timeout de leitura, o envio é registrado como não entregue. Faça trabalho pesado (ex.: baixar o print) de forma assíncrona, depois de responder.

8. Consultar registros

Para conferir o histórico sem depender do callback.

curl "{{ base_url }}api/dashboard?data_inicio=2026-07-01&data_fim=2026-07-08"

Sem parâmetros, retorna os registros do dia atual. Resposta:

{
  "registros": [
    {
      "id": 35,
      "ordem": 35,
      "processo": "0000511-77.2025.5.06.0018",
      "trt": "6",
      "grau": "1",
      "acao": "create",
      "status": "SUCESSO",
      "msg": "processo cadastrado com sucesso",
      "screenshot": "/screenshots/0000511-77..._create_SUCESSO_20260707_143512.png",
      "req_id": "3f7c1e2a-9b44-4d51-8a10-6e2f0c9d5b77",
      "data_hora": "2026-07-07T14:35:12.482910"
    }
  ]
}
Aqui o screenshot vem como caminho relativo. Para abrir, concatene com a base: {{ base_url }}screenshots/...

9. Prints de tela

Toda execução guarda um print — em sucesso e em erro.

O nome do arquivo segue o padrão <processo>_<acao>_<status>_<AAAAMMDD_HHMMSS>.png, e a imagem é servida diretamente: 

curl -O "{{ base_url }}screenshots/0000511-77.2025.5.06.0018_create_SUCESSO_20260707_143512.png"

Para exibir na sua interface, basta usar a URL absoluta que vem no callback:

<a href="{{ '{{ screenshot }}' }}" target="_blank" rel="noopener">
  <img src="{{ '{{ screenshot }}' }}" alt="print da execução" style="max-height:80px;border-radius:6px">
</a>

10. Para agentes de IA

Instruções diretas para um chat/agente que precise operar esta API.

Existe um contrato legível por máquina em GET /api/spec. Busque-o primeiro: ele traz endpoints, campos e valores válidos em JSON.

curl "{{ base_url }}api/spec"

Prompt pronto (cole no seu agente)

Você integra com a API de automação de Push do PJe.

BASE_URL = {{ base_url }}

Para CADASTRAR um processo no push:
  POST {BASE_URL}push/received
  JSON: { "numero_processo": "", "tribunal": "", "grau": "1|2",
          "acao": "create",
          "callbacks": [{ "url": "", "id": "", "token": "" }] }

Para EXCLUIR um processo do push:
  Mesmo endpoint, com "acao": "delete" e, SE VOCÊ TIVER, "codigo": .
  O "codigo" vem no retorno do cadastro e é POR GRAU. Sempre envie quando tiver:
  sem ele a exclusão é muito mais lenta.

REGRAS IMPORTANTES:
1. O POST responde 201 apenas confirmando o ENFILEIRAMENTO. O resultado real
   chega depois, via POST no seu callback.
2. O callback traz: id, status (SUCESSO|AVISO|ERRO), message, token, screenshot, codigo.
3. Exiba a "message" LITERALMENTE ao usuário — é o texto real do PJe. Não a
   substitua por texto genérico como "Concluído" ou "Erro".
4. Guarde o "codigo" recebido no create e reutilize-o no delete do mesmo grau.
5. Anexe o "screenshot" (URL absoluta) como comprovação, tanto em sucesso quanto em erro.
6. Responda o callback rapidamente (2xx); faça downloads de forma assíncrona.
7. Para consultar histórico: GET {BASE_URL}api/dashboard?data_inicio=AAAA-MM-DD&data_fim=AAAA-MM-DD

11. Erros comuns

O que a API responde quando algo está errado no envio.

HTTPMensagemComo resolver
400Payload deve ser um objeto JSON (dict) Envie um objeto JSON e o header Content-Type: application/json.
400Campo obrigatorio ausente: numero_processo Inclua numero_processo com o número CNJ completo.
500Variavel de ambiente ... nao configurada Problema de configuração do servidor — acione o responsável técnico.
502Falha ao encaminhar para a fila de processamento O RabbitMQ está indisponível. Tente novamente; se persistir, acione o suporte.
Status ERRO no callback não é erro de API — significa que o robô não conseguiu concluir no PJe. Leia a message e veja o screenshot para entender (ex.: falha de autenticação, perfil indisponível no TRT, processo não localizado).
